# DSH 开机动画插件调研（2026-10-17）

> 只读调研，**没有安装任何插件**。本机运行时：DSH `0.2.0-rc.2`，profile `web`，GUI <http://127.0.0.1:3080>。

## 0. 一句话结论

- 这个品类**已经卷起来了**：能查到的「开机/开屏/启动动画」插件有 **30+ 个**，主流实现是注册 `shell.overlay` 全屏浮层播视频/纯 CSS 动画。
- 你提到的**「莱茵生命」确实有专门的插件**：`Respawn-ID/dsh-rhine-splash`（一条命令，开屏动画 + 主题配色 + Logo 三合一，本机版本正好对口）。
- 另一个常被误认的「莱茵生命」是 `Galaxy-2001/Rhine-Lab-Codex-Theme` —— 那是**纯主题皮肤**，没有开机动画，它那套 14 秒折片动画是聊天页背景动效。
- 两条路各有代价：**莱茵专属包很新（★2、未上 npm）**；**通用包成熟（★289）但要自备素材**。

## 1. ⭐ 直接命中：莱茵生命开机动画

### `Respawn-ID/dsh-rhine-splash` —— 莱茵生命开屏动画

| 项 | 值 |
|---|---|
| 仓库 | <https://github.com/Respawn-ID/dsh-rhine-splash> |
| 版本 / 许可 | `v0.2.0`（2026-10-11）/ MIT |
| Star | ★ 2（2026-10-08 建库，10-11 最后推送） |
| 要求 | DSH **0.2.0-rc.2**（与本机一致） |
| npm | ❌ 未发布（只能在 GitHub / Release tgz / 本地目录装） |
| 内容 | ① 开屏动画（约 4.5 秒）② 界面配色主题 ③ 品牌 Logo 替换，**三者可分别开关** |
| 依赖 | 零依赖、无安装脚本 → 不触发 `allowBuilds` 构建授权、不需要版本豁免 |

安装（web profile）：

```bash
dsh plugin --profile web add github:Respawn-ID/dsh-rhine-splash
# 或锁版本
dsh plugin --profile web add 'github:Respawn-ID/dsh-rhine-splash#v0.2.0'
```

连不上 GitHub 时（本机刚才就常超时），下 Release 包再装：

```bash
# https://github.com/Respawn-ID/dsh-rhine-splash/releases/tag/v0.2.0
dsh plugin --profile web add "/绝对路径/dsh-rhine-splash-0.2.0.tgz"
```

播放规则与配置（来自仓库 README / `cordis.patch.yml`）：

- **每次启动只播一次**；**刷新页面不重播**（除非 `replayOnReload: true`）→ 必须**完全退出并重启** DSH 才看得到。
- 动画分两段：`REQUESTING ACCESS` → `PERMISSION AUTHORIZED` → `WELCOME TO DEEPSEEK HARNESS`，退场动画随机（`doors` / `decode` / `glitch` / `iris`）。
- 可调：`enabled`、`uiTheme`、`brand`、`logo`(`plate` / `cell`)、`title`、`subtitle`、`code`、`accentLight`、`accentDark`、`theme`、`exit`、`duration`(0–15000)、`maxWait`、`skippable`、`replayOnReload`。
- ⚠️ **不支持换成自己的图/视频**，素材是程序生成的内置原创图形（作者声明不含游戏官方素材，设计参考《明日方舟》特别映像「莱茵生命：访问」）。

![莱茵生命开屏（浅色）](https://raw.githubusercontent.com/Respawn-ID/dsh-rhine-splash/HEAD/screenshots/splash-light.png)

**代价**：★2 极新、未上 npm、聚合站无收录（需要自己审源码）；只在完整重启时播放 —— 本机是 LaunchAgent 托管，**重启会终止当前会话**；无自动更新，升级要卸载重装。

## 4. 实现路线与踩坑（给你选型用）

**四条路线**

1. **`shell.overlay` 全屏浮层 + `<video>`**（主流：NativeDog1 / Yiheng-guo-pro / dsh-boot-video / dsh-rhine-splash / KDDKBD / tenebris173 等）—— 片源可控、能做片库，但要处理自动播放策略、`moov` faststart、编解码兼容。
2. **纯 CSS / SVG / Canvas / WebGL 自绘**（zzbkl 44 秒六场戏、gxpppp SteamOS 七段、`dsh-550c-boot`、KylinQ01、whale-maid、inju0524 WebGL2 粒子、`dsh-erii-boot-splash`、`dsh-rhine-splash`）—— 零素材、体积小、不会黑屏，但观感上限靠设计。
3. **宿主注入 `webserver/index-inject` 抢首帧**（lxj5820 / `dsh-550c-boot` / gxpppp / stushansusu / oumaekumiko / zzbkl `immediately:true` / whale-maid）—— 在**文档解析阶段**就把底幕注入 `<head>`，抢在 shell 绘制前盖住 DSH 自己的 Loading 卡，所以不会先闪一下主界面；代价是要碰宿主注入点，**官方桌面版 `webServer.tapIndex` 可能永不执行**（KylinQ01 就因此要单独维护 `official-desktop` 分支）。
4. **外部启动器 / 桌面壳**（`dsh-splash-launcher` Windows WPF+WebView2；`samsam560` 的退场补丁）—— 在服务起来之前就把浏览器开屏放出来，专治"等服务启动时的白屏"，但只覆盖 Windows / 只覆盖冷启动。

**已知坑（各 README 共同提到的）**

- **浏览器缓存**：客户端 bundle 是 `max-age=31536000, immutable`，而 URL 上的 `rev` 是**进程 nonce**、不随内容变 → 装完必须 **Ctrl+Shift+R 硬刷新**（普通 F5 不够）。
- **装完要重启 DSH 服务**：bundle 层是启动时装配的。本机是 LaunchAgent 托管，重启会终止当前会话，用 [`.dsh-web/restart-once.sh`](../.dsh-web/restart-once.sh)。
- **黑屏多半是 `moov` 没前置**：`ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`（无损重排）。NativeDog1 有 25 秒卡顿看门狗，超时自己关掉浮层 → 症状是"点开什么都没有"；`stushansusu` 还要求 **poster 必须是第一帧**，否则开机先显示片尾再跳回开头。
- **z-index 之争**：浮层常见值是 `2147483000`，装两个片头插件会互相压盖；**同类插件应当只留一个**（whale-maid 会主动检测让位，`dsh-550c-boot` 片头与 UEG 界面也互斥）。sessionStorage / localStorage 键通常各自独立，所以"都装了"不会互相清记录，但视觉上会打架。
- **静音自动播放 + 真全屏都需要用户手势**：所以默认静音自动播，点一下才开声音/进全屏。
- **客户端插件绝不能静态 `inject`**：client loader 把任何非 `active` 条目当致命错误（`web boot: N entry did not activate`），静态 inject 某个宿主给不出的服务会让**整个 GUI 打不开**。正确做法是动态注入 `ctx.inject([...], cb)`，宿主给不出时静默闲置。（NativeDog1 README 用整节解释这个事故。）
- **同名/同包名冲突**：`tenebris173` 的 fork 与上游 `KDDKBD` **同包名 `dsh-splash-animation`，不能同装**；包名必须与 profile bundles 里那行一致，否则被静默跳过。

### 4.1 兼容闸门速记（针对本机 `0.2.0-rc.2`）

DSH 0.2.0 起会把 `peerDependencies` / `engines.dsh` 对不上的插件**整包跳过且不报错**（现象是"装上了但没反应"）。

| 明确不会/已经声明不会被跳过 | 依据 |
|---|---|
| `NativeDog1/dsh-boot-animation` | README 明说**刻意不声明任何 `@deepseek-ai/dsh-*` peer**，因此免疫 |
| `lxj5820/dsh-boot-animation` | README 专节说明**已适配 0.2.0-rc.2**（改用 `Config` + `.volatile()`） |
| `dsh-550c-boot` | `dsh.engines.dsh: ">=0.2.0-rc.1"` |
| `@linxin666/dsh-web-start-ui` | `peerDependencies["@deepseek-ai/dsh"]: ">=0.2.0-rc.2"`（本批唯一显式声明 rc.2 peer 的） |
| `KDDKBD/DeepSeek-splash-animation` | 无 peer 声明；聚合站记录 **0.2.0-rc.2 实测通过**（2026-10-08） |
| `Galaxy-2001/Rhine-Lab-Codex-Theme` | README 明确"DSH 把 prerelease 纳入运行时检查，**不需要豁免**" |
| `Yiheng-guo/dsh-boot-animation-pro`、`zzbkl/dsh-cold-boot` | `dsh.engines.dsh: ">=0.1.5-rc.1"` |
| `Respawn-ID/dsh-rhine-splash` | 无依赖无脚本，README 标注目标即 **0.2.0-rc.2** |

**需要自己先验的**（未声明 `engines.dsh` / 未说明）：`gxpppp/dsh-boot-anim`、`KylinQ01/dsh-startup-animation`、`tenebris173/DeepSeek-splash-animation`、`whale-maid`（无 `@deepseek-ai/dsh-*` peer，按机制**推断**安全，但 README 未明说）。

⚠️ **prerelease 陷阱**：`^0.2.0-rc.2` **不覆盖** `0.2.1-rc.1`（预发布只满足 major.minor.patch 完全相同的比较器）。所以上面这些"已声明"的插件，**DSH 一升级就要重新核对**。

  - star 数是 2026-10-17 的快照，且 GitHub Search 有 19~34 条量级的召回上限 + dshfind 标签页只收 10 个 → **总数只能给区间（约 20~22），不是精确值**，未写英文描述的中文仓库容易漏。
