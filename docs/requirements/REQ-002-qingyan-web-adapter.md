# REQ-002 · 清言网页适配器（回读与桥接）

| 项 | 值 |
|---|---|
| 状态 | 草稿（待评审） |
| 日期 | 2026-10-31 |
| 关联 | `dsh-external-discuss` 插件、REQ-001（形态 C 依赖本文档） |
| 前提 | 只改造「网页清言」这一侧的接入能力，不改动审核判定逻辑 |

---

## 1. 背景与问题

现有 `dsh-external-discuss` 插件解决的是**单向投递**：页面按钮 → 扩展 → 清言网页 → 新建对话 / 重命名 / 粘贴 / 发送。发送完就返回，**不等待、不读回**。

要把清言当作可编程的问答端点（REQ-001 的形态 C），必须补齐三件事：

1. **等它说完**——现在点完发送就结束，不知道回复何时完成；
2. **把话拿回来**——现在一个字都没回传；
3. **说清失败原因**——现在未登录、风控、发送失败都表现为同一种「某步骤失败」。

---

## 2. 目标

| 编号 | 目标 | 可观测的成功标志 |
|---|---|---|
| G1 | 给定一段提示词，能返回**完整**回复文本 | 与页面显示逐字比对一致 |
| G2 | 能准确判断「回复已结束」 | 不把加载中/半截内容当完整回复 |
| G3 | 失败可分类 | 至少区分未登录、风控、发送失败、超时、空回复 |
| G4 | 宿主可发起 | 不依赖用户点页面按钮 |
| G5 | 失败不等于成功 | 任何异常都返回明确错误，绝不返回空文本冒充回复 |

---

## 3. 范围

### 3.1 包含

- **P1（扩展自足）**：等待回复结束、抓取回复文本、错误分类；
- **P2（桥接）**：宿主发起任务、扩展执行、结果回投；
- 抓取方案选型与降级；
- 超时、重试、幂等；
- 验收指标与实测方法。

### 3.2 不包含

| 排除项 | 理由 |
|---|---|
| 审核判定逻辑（APPROVE/REJECT 解析） | 属于 REQ-001 |
| 多轮对话管理、上下文续接 | 本期一次一问 |
| 文件上传 / 图片理解 | 本期只支持纯文本 |
| 清言账号管理、风控对抗 | 只做检测与上报，不做绕过 |
| 除清言外的其他站点 | 本期只做清言 |

## 5. 目标能力

### 5.1 P1：回读（扩展单方面可完成）

| 能力 | 要求 |
|---|---|
| 等待结束 | 以「回复流结束」为准，而非固定等待时长 |
| 抓取文本 | 返回完整回复正文，保留代码块与换行 |
| 错误分类 | 见 §6.3 |
| 幂等 | 同一任务重复触发不重复发送 |
| 可观测 | 返回耗时、步骤流水，便于排障 |

### 5.2 P2：桥接（宿主可发起）

| 能力 | 要求 |
|---|---|
| 任务投递 | 宿主创建任务，扩展取走执行 |
| 结果回投 | 扩展把结果写回任务 |
| 断线恢复 | 任一侧重启后自动恢复，任务不丢 |
| 超时 | 任务级超时，过期任务作废 |
| 安全 | 仅本机回环可访问；载荷大小限制 |

## 6. 接口约定

### 6.1 扩展内部消息（P1）

```jsonc
// 请求
{
  "type": "qingyan:ask",
  "text": "待发送的完整提示词",
  "options": {
    "newConversation": true,   // 是否新建对话，默认 true
    "title": "可选：会话标题",
    "timeoutMs": 180000        // 等待上限
  }
}

// 响应
{
  "ok": true,
  "reply": "完整回复文本",
  "errorClass": null,          // 失败时为 §6.3 的枚举
  "durationMs": 42311,
  "steps": ["已点击新对话", "已重命名", "已写入正文", "已发送", "回复已结束"]
}
```

### 6.2 宿主 HTTP 接口（P2）

| 方法 | 路径 | 用途 |
|---|---|---|
| POST | `/api/qingyan-bridge/jobs` | 创建任务，返回 `jobId` |
| GET | `/api/qingyan-bridge/poll?wait=25` | 扩展长轮询取任务；无任务返回 204 |
| POST | `/api/qingyan-bridge/jobs/{id}/result` | 扩展回投结果 |
| GET | `/api/qingyan-bridge/jobs/{id}` | 宿主查询任务状态与结果 |

约束：

- 仅接受本机回环地址；
- 任务有效期默认 10 分钟，过期作废；
- 载荷上限 1 MB（超出直接拒绝）；
- 同一 `jobId` 的结果只接受一次（幂等）。

### 6.3 错误分类

| 枚举 | 判定依据 | 是否重试 |
|---|---|---|
| `EXTENSION_ABSENT` | 宿主收不到扩展轮询 | 否，直接回退 |
| `NOT_LOGGED_IN` | 页面出现登录入口 / 会话列表为空且无输入框 | 否，提示登录 |
| `RISK_CONTROL` | 出现验证码 / 滑块 / 风控提示 | **否**，立即停止 |
| `PAGE_NOT_READY` | 输入框或发送按钮找不到 | 是，限 2 次 |
| `SEND_FAILED` | 点击发送后正文仍在输入框内 | 是，限 1 次 |
| `TIMEOUT` | 超过 `timeoutMs` 仍未结束 | 是，限 1 次 |
| `EMPTY_REPLY` | 流结束但文本为空 | 否 |
| `NAVIGATION_FAILED` | 新建对话 / 重命名失败 | 重命名失败可降级继续；新建失败即失败 |

**铁律**：`EMPTY_REPLY`、`TIMEOUT`、`RISK_CONTROL` 一律不得被上层当成有效回复。

## 7. 抓取方案

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 拦截页面自身的流**（推荐） | 在页面主世界注入钩子，包住 `fetch`，旁路复制发往对话接口的响应流，按 SSE 帧累积文本 | 完成信号精确；不依赖 DOM 结构；不受改版影响 | 需主世界注入（`world: "MAIN"`、`document_start`） |
| B. 轮询 DOM | 定时读最后一条助手消息 + 观察停止按钮消失 | 实现简单 | 依赖选择器；「结束」只能靠猜 |

**决策**：以 A 为主，B 作为兜底（A 失效时自动降级，并在结果中标注使用的方案）。

技术约束：内容脚本默认运行在隔离世界，读不到页面自身的 `fetch`，必须声明主世界脚本且**在页面代码执行前**完成包装，否则会漏掉请求。

## 8. 超时与重试

| 项 | 默认值 | 说明 |
|---|---|---|
| 单次问答超时 | 180s | 覆盖长文与慢回复 |
| 发送后首字节超时 | 30s | 超时视为发送失败 |
| 重试次数 | 1 | 仅对可重试错误 |
| 任务有效期 | 10 分钟 | 桥接层 |
| 长轮询等待 | 25s | 无任务返回 204 |

**重试不改变幂等**：同一任务重试时，若上次已发送成功，只重试「等待+抓取」，不重复发送。

## 9. 验收标准

| 编号 | 验收标准 | 验证方式 |
|---|---|---|
| AC-01 | 20 次问答中成功返回完整回复 ≥ 18 次（成功率 ≥ 90%） | 实测统计 |
| AC-02 | 回复文本与页面人工比对 10 例，逐字一致 | 人工比对 |
| AC-03 | 未登录时返回 `NOT_LOGGED_IN`，且**不误点**任何按钮 | 退出登录实测 |
| AC-04 | 出现风控/验证码时返回 `RISK_CONTROL` 且不重试 | 构造或观察 |
| AC-05 | 超时返回 `TIMEOUT`，**不返回半截文本** | 构造慢响应 |
| AC-06 | 5000 字以上提示词可完整发送并回读 | 长文实测 |
| AC-07 | 桥接端到端（宿主发起到拿到结果）P95 ≤ 90s | 10 次统计 |
| AC-08 | 页面刷新或扩展重载后，轮询自动恢复，任务不丢 | 中途刷新实测 |
| AC-09 | 不新增任何外部依赖；不读取与清言无关的页面数据 | 代码审查 |
| AC-10 | 连续 10 次问答后账号无异常提示 | 观察 |

> AC-01 的 90% 是**初始门槛**，实测后按真实数据调整；若低于门槛，先修可靠性再谈接入审核。

## 10. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 清言前端改版 | 选择器/流结构失效 | 抓取走 A 方案；所有候选文本集中在配置对象；内置探针 |
| 账号风控 | 任务中断甚至账号受限 | 检测即停、不重试、低频使用；单次审核仅一次调用 |
| 隐私 | 提示词外发第三方 | 发送前密钥特征扫描；可配置关闭外发 |
| 延迟 | 审核变慢 | 设超时；超时回退人工 |
| 扩展被浏览器挂起 | 桥接断开 | 长轮询保活 + 自动重连 |
