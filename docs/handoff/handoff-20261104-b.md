## §5 陷阱与教训（每条都带解法）

1. **`not allowed for this Session` ≠ 模型不存在**。先查插件是否加载（`~/.dsh/profiles/web/cordis.patch.yml` 里有 `dsh-subagent-policy-fallback` 这一行、且 `node_modules/dsh-subagent-policy-fallback` 软链没悬空）。插件没加载时这条错误会**静默回来**，没有任何提示。
2. **插件刻意不写进 `package.json` 的 `dsh.profile.bundles`**：两处都声明会在重启时让同一 id 被插两次。唯一声明处是 profile 的 `cordis.patch.yml`。改这里前先看那一行的注释。
3. **`list_subagent_models` 不是模型全集**，它只列「当前会话策略允许的路由」；没有策略时它退化成只回父 provider。查模型看 `cordis.patch.yml` 的 `llm-pi-ai.config.providers`。
4. **高风险 PR 闸门没有 override 开关**。`gate.mjs` 命中高风险直接 `E_POLICY`，受支持的正式路径只有：用户当场同意 → `merge-pr.sh <PR> --no-review --reason "…"`（写跳过审计）→ PR 上补一条「跳过审核闸门说明」评论（模板见 `docs/pipeline/README.md` §四）。代价：该 PR 在统计口径上**不计入已审核**，即使它实际跑过审核。今天 #268、#270 都是这么过的。
5. **reviewer 是只读沙箱，跑不了 git**。任务书里必须**直接把 HEAD 的完整 SHA 写给它**，否则它要么判定 `ESCALATE`，要么判定行的 SHA 对不上导致 `record` 失败（今天第一轮就是这么废的）。
6. **`record` 需要 12 位 base32 的 `nonce`**（`A-Z2-7`），且 reviewer 响应里的判定行必须用同一个 nonce；请求里缺 nonce 会 `argError` 退出 2，merge 随后停在 gate（`E_IO`）——这是 fail-closed，别去改记录。
7. **`gh` 在受限沙盒下报 `HTTP 401: Requires authentication`**，不是令牌过期（详见 `~/.dsh/AGENTS.md` §5）；`git` 走 SSH 不受影响。
8. **opencode 免费档会耗尽**（`Free usage limit reached`）。现在执行面是原生子代理 + go 订阅的 mimo，**不受那个池影响**；真要用 codebuddy 顶替 executor，必须用户逐次授权。
9. **桌面/浏览器侧有人正开着会话时不要随意重启 dsh web**。今天所有 profile 改动都靠 `patchReload: live` 完成，一次没重启。
10. **刷新共享包不能靠 `pnpm update`**：一律 `rm -rf node_modules pnpm-lock.yaml && pnpm install`，并用 `doctor` 验构建标识（不是看 install 成功）。
11. **注入式包装层必须透传调用方 options**：`(cwd, name) => fn(cwd, name, { runner })` 这种写法会悄悄吞掉 `{ force: true }`。单测只注入假 git 时抓不到，要断言**真实发出的 argv**。

**代码红线**：只走 pipeline（issue → worktree → PR → 审核 → 合并）；禁止直推 `main`；squash 唯一；多行 body 用 `--body-file`；`gh api` 走 REST。

**上一棒（同一天早些时候）的错，防重蹈**：把「mimo 不存在」当结论（实际是策略没采样）；把「新会话就能用」写进交接（种子会话一样不行）；把 `gh pr merge --delete-branch` 的失败当现场问题（其实是包里的 bug，已修）。
