# dsh-plugin-zhihu-sidebar

把知乎数据放进 DeepSeek Harness Web 的**右侧栏**：热榜、知乎搜索、我的创作。
数据全部来自知乎官方命令行工具 [`zhihu-cli`](https://developer.zhihu.com)，本插件只负责调用、
判定、缓存与限流保护，不直连知乎任何 HTTP 接口。

> **当前进度：两阶段都已完成。** 宿主侧三条只读接口 + 浏览器侧右侧栏页。
> 装好后需要**重启 dsh web** 才能看到右栏里的「知乎」卡片。

## 怎么打开

1. 打开 dsh Web，点右上角的右侧栏按钮把右栏展开。
2. 在右栏的**引导页**里找卡片「**知乎热榜 / 搜索 / 我的创作**」，点它。
3. 右栏会多出一个「知乎」tab，**一个 tab 里装三个视图**，用顶部的分段切换：

| 分段 | 看到什么 | 怎么取数 |
|---|---|---|
| **热榜** | 当前社区热点的前 N 条（默认 30），带排名、摘要与缩略图 | 点右上角「加载热榜」/「刷新热榜」 |
| **搜索** | 知乎站内搜索结果，带标题、作者、摘要、原文链接 | 输入关键词后回车，或点「搜索」 |
| **我的创作** | 当前 Access Secret 所属账号的**公开**创作，带类型与发布时间 | 点右上角「加载我的创作」/「刷新我的创作」 |

每条结果都保留原文链接（新标签页打开），摘要不是正文。
**没有「打开即加载」，也没有任何轮询**——每次取数都由你点一下按钮触发。

### 热榜为什么要点一下才出数据

热榜每天只有 **100 次**额度（见下面「每日额度」）。任何自动刷新都会把它刷光，
所以这个界面**只在用户点击时请求一次**，并且：

- 取过一次后，按钮进入 **30 分钟**冷却，期间显示「29:41 后可刷新」并禁用；
- 按钮的悬停提示给出下次可刷新的**绝对时刻**；
- 宿主侧还有 5 分钟缓存：冷却结束再点，多半直接命中缓存，不消耗额度。

搜索（5000 次/天）与我的创作（10000 次/天）额度宽裕，但同样做成「点了才发」，
让每一次额度消耗都可解释。

### 出错时看到什么

| 情况 | 界面表现 |
|---|---|
| 没配密钥（`auth_required`） | 「需要知乎 Access Secret」+ 按钮「**去申请密钥**」，直达知乎开放平台个人中心 |
| 被限流（`rate_limited`） | 「被知乎限流，1:30 后可重试」，倒计时逐秒走；结束前按钮禁用 |
| 今日额度用完（`quota_exhausted`） | 「今日额度已用完（剩余 0 次）」，该视图的操作禁用（其它视图不受影响） |
| 限流期拿到旧数据 | 列表照常显示，顶部黄条说明「显示的是缓存数据」 |
| 参数错误 / 业务错误 / 网络 / 超时 / 服务端 / 找不到 CLI / 凭证库不可用 | 一行中文原因 + `zhihu-cli` 的原始消息 |

## 装好之后能做什么

| 能力 | 数据来源 | 说明 |
|---|---|---|
| 知乎热榜 | `zhihu-cli hot --limit N` | 当前社区热点，1–30 条，默认 30 |
| 知乎搜索 | `zhihu-cli search zhihu --query "..." --count N` | 标题 / 作者 / 摘要 / 原文链接，1–10 条 |
| 我的创作 | `zhihu-cli me contents --limit N` | 当前 Access Secret 所属账号的公开创作 |
| 能力清单 | `zhihu-cli capabilities` | 免密钥，作为参数边界的运行时来源 |

## 前提

1. 已安装 `zhihu-cli`（探针阶段用的是 `0.6.1`）。
2. 已通过 `zhihu-cli auth set` 或 `zhihu-cli init` 配好 Access Secret。
3. 插件能被执行到 CLI 二进制。默认路径是插件目录下的 `.probe/bin/zhihu-cli`，
   正式部署时应换成系统安装路径或 `.runtime/`：
   在 `~/.dsh/profiles/web/package.json` 里把本插件加为 `link:` 依赖后，无需额外配置；
   需要改路径时在插件配置里传 `cliPath`。

## 密钥：插件永远不接触明文

Access Secret 存在 **macOS 系统凭证库（Keychain）**，由 `zhihu-cli` 自己读取。
本插件：

- 不读 Keychain；
- 不读 `.env`；
- 不向子进程传 `ZHIHU_ACCESS_SECRET` 或任何密钥类环境变量；
- 只给子进程最小环境（`PATH` / `HOME` / `TMPDIR` / `LANG` / `LC_ALL`）。

唯一能看到凭证的是 `zhihu-cli` 进程本身。

## 每日额度与限流

知乎开放平台按自然日计额度（实测值）：

| 能力 | 每日额度 | 插件默认本地上限 |
|---|---:|---:|
| 热榜 | 100 | 80 |
| 知乎搜索 | 5000 | 500 |
| 我的创作（user_data） | 10000 | 1000 |

插件故意把本地上限压得比真实额度低，留出调试与手动的余量。除此之外：

- **结果缓存**：热榜 5 分钟、搜索 2 分钟、我的创作 10 分钟、能力清单 24 小时；
- **串行调用**：同一时刻只跑一个 `zhihu-cli` 子进程，同一请求并发时只跑一次；
- **限流退避**：命中退出码 4 或业务码 `30001` 后，该能力进入冷却（30s → 60s → 120s，封顶 5 分钟），
  冷却期内不发真实请求：有旧数据就返回旧数据（`stale: true`），没有就返回 `rate_limited`；
- **额度查询低频化**：`zhihu-cli quota` 本身不消耗业务额度，但**会触发限流**，
  所以插件最多每 30 分钟查一次，其余时间只靠本地计数。

界面侧不重复实现这些闸门，只负责「把信封翻译成界面」；额度、缓存、退避一律由宿主层决定。

## 宿主接口

全部只读、全部 **loopback-only**（只接受本机浏览器请求），前缀 `/api/dsh-zhihu-sidebar`：

| 方法 | 路径 | 参数 |
|---|---|---|
| GET | `/hot` | `limit`（1–30，默认 30） |
| GET | `/search` | `q`（必填）、`count`（1–10，默认 10） |
| GET | `/contents` | `limit`（1–50，默认 20） |
| GET | `/capabilities` | — |
| GET | `/status` | —（队列 / 缓存 / 冷却 / 额度快照） |

成功：`{ "ok": true, "data": {...}, "cached": false, "fetchedAt": 1761... }`。
失败：`{ "ok": false, "reason": "auth_required" | "rate_limited" | "quota_exhausted" | ... }`，
HTTP 状态码随原因变化（401 / 429 / 503 …）。

## 开发

```bash
cd dsh-zhihu-sidebar
node --test "test/*.test.mjs"      # 116 个用例
node --check lib/index.js
node --check lib/client.js
```

浏览器半边是**免构建**的手写 bundle（`window.__ModuleLoader__.load({ id, factory })`），
单测用 `test/client-harness.mjs` 把它当经典脚本加载，因此测的是真实发布文件。
纯逻辑（请求 URL、信封判定、热榜冷却、时间换算、行映射）都挂在 `exports.__internals` 上。

测试**不会调用真实 `zhihu-cli`**：所有子进程都是 `test/fixtures/fake-cli.mjs`，
按预设场景返回 stdout / 退出码，因此不消耗额度、不触发限流；界面侧测试全部用合成数据。

## 已知限制

- 热榜必须要有 Access Secret：无密钥时 CLI 对所有数据命令一律退出码 3，没有匿名降级。
- **不支持翻页**：搜索与我的创作只取第一页，页脚会提示「还有更多结果」，但没有「下一页」按钮。
- **不显示赞 / 评论 / 收藏数**：宿主规范化只保留标题、链接、作者、摘要、类型与发布时间。
- 打开入口只有右栏引导页卡片：没有会话头部按钮，也没有设置页。
- 界面文案中英双语，跟随 dsh 的语言设置。
