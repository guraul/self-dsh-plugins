# 知乎选题助手（Chrome 扩展）

从知乎**创作者推荐池**和**关键词搜索**里挑出值得回答的问题：浏览量、回答数、关注数、提问时间，
在本地筛选、按流量潜力排序。零依赖、无构建步骤，直接以 unpacked 方式加载。

> 这是 `dsh-zhihu-sidebar` 插件的配套扩展，独立于 DSH 运行，不需要 DSH 在跑。

## 怎么加载

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 打开右上角「开发者模式」。
3. 点「加载已解压的扩展程序」，选择本目录（`dsh-zhihu-sidebar/extension`）。
4. 建议把「知乎选题助手」固定到工具栏。

改动代码后回到 `chrome://extensions` 点该扩展的刷新按钮即可，无需重新打包。

## 怎么用

1. 先在浏览器里打开任意 `https://www.zhihu.com` 页面，并确认**已登录**（扩展复用这个标签页的登录态）。
2. 点扩展图标打开弹窗。
   - 如果没有知乎标签页，弹窗会提示「请先打开一个知乎页面」，并给一个「打开知乎」按钮。
3. 取数：
   - **拉取推荐池**：默认拉 2 页（40 条），可在「页数」里调整；推荐池总量约 10000 条，可继续翻页累积。
   - **按关键词搜索**：输入关键词后点「按关键词搜索」，每个词最多取 40 条（接口上限约 42 条）。
   - 两种来源的结果会自动按问题 id 合并去重，新拉到的排在前面。
4. 筛选与排序：
   - 「最小浏览」「最大回答」「标题过滤」可单独或组合使用，留空即不过滤。
   - 快捷按钮：
     - **高流量低竞争**：浏览 ≥ 10000 且 回答 ≤ 100
     - **抢首发**：回答 = 0 且 提问时间在 7 天内（无提问时间的条目不会被这条误删）
     - **全部**：清空筛选条件
   - 排序：
     - **每回答流量**（默认）= 浏览 / max(回答数, 1)
     - **蓝海指数** = 关注数 / max(回答数, 1)
     - **浏览量**：按浏览降序
     - **最新**：按提问时间降序，无时间排最后
5. 点标题在新标签页打开问题；推荐池条目在标题下方以浅色小字显示推荐理由。
6. 底部状态栏显示「已加载 N 条 · 显示 M 条」；右上「清空」会同时清掉内存与本地缓存。

## 数据从哪来

扩展在**你已登录的知乎页面上下文**里调用知乎自己的接口：

| 来源 | 接口 | 说明 |
|---|---|---|
| 推荐池 | `/api/v4/creators/question_route/pc_member_related/recommend` | 约 10000 条，字段齐全，`visit_count` 为浏览数，自带 `created` |
| 关键词搜索 | `/api/v4/search_v3?t=question&q=...` | 每词约 42 条，`visits_count`（复数）为浏览数，无 `created`，标题含 `<em>` 高亮 |

请求由 content script 发起，走**同源 fetch（`credentials: 'include'`）**，Cookie 由浏览器自动携带。
**扩展不读取、不存储、不外传任何 Cookie 或登录凭证**，也没有任何上报/统计代码。

取到的数据只存在于两个地方：

- 弹窗内存（关闭即丢）
- `chrome.storage.local` 缓存（最多 2000 条，供下次打开弹窗时恢复，可一键清空）

## 已知限制

- **推荐池是个性化推荐**：结果与账号画像（历史赞同/关注的话题）强绑定，换账号结果会明显不同。
- **搜索池量少、相关性优先**：每个关键词约 42 条，按相关度排序且浏览中位数很低（实测约 23），
  适合定向找细分问题，不适合发现爆款；`sort=upvoted_count` 参数实测无效。
- **两个接口的浏览字段名不同**：推荐池是 `visit_count`，搜索池是 `visits_count`，代码已兼容；
  若知乎再改字段名，需要同步更新 `lib/logic.js` 的 `normalize`。
- **搜索池没有提问时间**：`created` 记为 `null`，「最新」排序里排最后，「抢首发」不会过滤它们。
- **接口可能随知乎改版失效**：返回 401/403 或带 `error` 字段时弹窗会提示「知乎未登录」，
  若确认已登录仍报错，多半是接口变更或被风控，需要更新 `content.js` 的 URL 与解析。
- 串行请求、每次间隔约 900ms，页数开太大会比较慢（这是为了降低风控概率）。
- 浏览/回答等数字是接口快照，不同时间拉到的不一致属正常。

## 目录

```
extension/
├── manifest.json       MV3 清单
├── content.js          在知乎页面里同源取数（只取原始数据）
├── popup.html/.css/.js 弹窗 UI：合并、筛选、排序、缓存
├── lib/logic.js        纯逻辑（归一化/去重/筛选/排序/格式化），popup 与测试共用
└── test/logic.test.mjs node --test 单测
```

跑测试：`cd extension && node --test "test/*.test.mjs"`（Node 22+，无第三方依赖）。
